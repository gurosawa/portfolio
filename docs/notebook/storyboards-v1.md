## 공통 화면 규칙

- 제목, 본문, 근거, 관련 글을 먼저 읽을 수 있게 한다. 동작을 보지 않아도 결론이 이어져야 한다.
- 주황색은 현재 단계나 선택에 사용한다. 정답·오답은 문자와 모양을 함께 사용하며 색만으로 구분하지 않는다.
- 데스크톱은 본문 약 42rem, 관련 도식이 옆에 머무는 구조다. 모바일은 본문 뒤에 해당 도식이 순서대로 온다. 긴 화면 고정이나 가로 스크롤 서사는 사용하지 않는다.
- 조작 결과는 도식과 짧은 텍스트 요약에 함께 반영한다. 키보드 조작, 초기화, 모션 끄기, 장별 직접 주소가 필요하다.
- 고유 글 주소와 장 ID를 먼저 확정한다. 기존 OPS·SEC 글의 주소와 Act anchor는 바꾸지 않는다.
- 본문의 표현 형식은 분야와 별개다. 공개 구현 시 공통 shell 선택을 `/zktls/` 경로만으로 판단하지 않도록 확장하되 기존 SEC 레이아웃은 보존한다.
- 연구 기반 해설, 설명용 계산, 직접 측정 결과를 나눈다. 본문 출처의 명칭과 작성자의 문장은 실제 저자·발표자의 직접 인용처럼 보이지 않게 한다.

## AI-01: 평가의 관점이 바뀌는 이야기

원고: [정답률이 올랐는데, 풀 수 있는 문제는 줄었다?](drafts/ai-01-pass-at-k.md)

**주인공:** 같은 네 문제에 답하는 가상 모델 A와 B. **독자의 변화:** 점수 한 개를 보던 상태에서 생성 예산과 선택 기준까지 읽는 상태로 간다.

| 장면 ID               | 본문의 질문                                      | 화면                                                          | 독자의 조작 / 기본 상태                                                    |
| --------------------- | ------------------------------------------------ | ------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `first-answer`        | 한 번의 응답에서 어느 쪽이 좋은가                | 네 문제와 A·B의 문제별 성공 확률, 기대 pass@1                 | 초기 k=1. A 45%, B 25%                                                     |
| `more-attempts`       | 기회를 더 주면 무엇이 달라지는가                 | 문제별 `1-(1-p)^k`와 전체 평균. 축에 시도 횟수·기대 점수 명시 | k=1 / 2 / 4 / 8 선택. 값은 매번 같은 계산으로 결정                         |
| `training-change`     | 학습 단계를 비교하는 것과 k를 늘리는 것은 같은가 | 가상 예제와 별도인 논문 결과 설명                             | 조작 없음. 논문 버전·Table 4 표시                                          |
| `select-answer`       | 정답 후보를 골라낼 수 있는가                     | 미리 정한 답 4개의 묶음. 최종 선택 상태와 정답 포함 상태 분리 | 초기엔 선택 없음. 선택한 뒤 정답 확인 버튼. 모델 성능 점수로 합산하지 않음 |
| `evaluation-contract` | 실제 서비스에서는 무엇을 기록할까                | 생성 수·선택 방법·최종 성공·작업량을 나란히 정리              | 정적 읽기. 관련 글 연결                                                    |

### 계산 데이터와 표시

```json
{
	"sourceKind": "illustrative-assumption",
	"modelA": [0.9, 0.9, 0, 0],
	"modelB": [0.25, 0.25, 0.25, 0.25],
	"attemptOptions": [1, 2, 4, 8],
	"initialAttempts": 1
}
```

모델별 결과는 `mean(probabilities.map(p => 1 - (1 - p) ** k))`다. 모델 평균 확률을 먼저 구해 공식에 넣으면 안 된다. 표시는 백분율 소수 둘째 자리까지 반올림한다. 입력 확률을 독자가 바꾸는 기능은 첫 구현에 넣지 않는다. 설명 문구는 같은 분포에서의 독립 반복 생성이라는 가정을 명시한다.

논문 결과를 이 곡선에 겹쳐 그리지 않는다. 학습 단계가 바뀌는 장면에는 Table 4를 별도로 표시한다. 고정 분포에서 k를 늘릴 때 기대 pass@k가 감소하는 애니메이션은 금지한다.

`select-answer`는 4개의 미리 작성한 후보 중 정답이 포함된 상황을 설명하는 별도 예제다. 유효한 pass@k 평가 샘플로 취급하지 않고 통계 그래프와 수치 연동하지 않는다. ‘직접 고르기’ 전에도 본문은 읽힌다.

| 주장                                 | 근거                                                      | 초안에서의 사용                        |
| ------------------------------------ | --------------------------------------------------------- | -------------------------------------- |

| 학습 단계별 두 지표의 변화           | 같은 논문 §4.4·Table 4                                    | Omni-MATH-Test의 GRPO 150·450스텝 비교 |

### 구현 후 확인할 사항

k의 기본값·복원·초기화, 문제별 계산과 평균, 반올림, 정답 선택 상태, 장 직접 진입, 모션 감소, 모바일 가로 넘침을 확인한다. 조작용 예제의 점수와 실제 모델의 성능이 혼동되지 않는지 읽어서 확인한다.

## AI-02: 누가 응답을 만들고 무엇이 모델을 바꾸는가

원고: [AI에게 답을 보여줄까, 직접 풀게 할까?](drafts/ai-02-learning-signals.md)

**공통 예제:** `8 + 3 × 4`. 정답 20, 설명용 오답 44. **독자의 변화:** 학습법 이름을 외우는 대신 응답의 출처와 학습 신호를 구분한다.

| 장면 ID                  | 표시 요소                                                        | 본문과의 관계                  | 형식        |
| ------------------------ | ---------------------------------------------------------------- | ------------------------------ | ----------- |
| `one-problem`            | 문제·설명용 오답·정답                                            | 무엇을 고칠지 제시             | 정적 예제   |
| `sft`                    | 준비된 목표 응답 → 학생 모델 갱신                                | 모범 응답을 따라 학습          | 정적 순서도 |
| `rlvr`                   | 학생 응답 → 최종 답 평가 → 보상 → 학생 갱신                      | 생성 결과의 보상 사용          | 정적 순서도 |
| `on-policy-distillation` | 학생 응답 → 같은 접두사를 보는 교사·학생 → 분포 차이 → 학생 갱신 | 학생의 경로에서 받는 학습 신호 | 정적 순서도 |
| `choose-signal`          | 세 방식의 입력·신호·필요 조건                                    | 선택 기준을 한눈에 비교        | 읽기용 표   |

이 글에는 스크롤 고정이나 동작 전용 상태를 넣지 않는다. 세 가지 순서도는 같은 시각 언어로 만들어 화살표의 출발점과 피드백 위치가 눈에 들어오게 한다. 도식마다 완전한 설명이 있으며 세 방식을 탭 안에 숨기지 않는다.

토큰별 피드백의 진하기를 추가한다면 ‘개념적 강조’로만 표현한다. 실제 교사 log probability나 확정된 정오 판정처럼 수치를 붙이지 않는다. RLVR에서는 현재 예제가 최종 답 보상이라는 점을 도식과 캡션에 적는다. 모든 RL이 같은 피드백 구조를 갖는다고 쓰지 않는다.

## AI-06: 요청 하나의 경로를 따라가기

원고: [모든 질문에 가장 비싼 모델을 써야 할까?](drafts/ai-06-model-orchestration.md)

**주인공:** ‘지난달 매출 감소 원인’이라는 가상의 요청. **독자의 변화:** 모델 단가를 보던 상태에서 도구·권한·재시도·최종 응답까지 확인한다.

| 장면 ID        | 화면 상태                         | 독자의 조작 / 기본 상태                    | 핵심 설명                        |
| -------------- | --------------------------------- | ------------------------------------------ | -------------------------------- |
| `request`      | 요청과 필요한 자료·계산·설명 표시 | 조작 없음                                  | 작업 분해                        |
| `route`        | 내부 검색 → 계산 → 모델 설명 경로 | 기본값 ‘내부만’                            | 데이터가 어디로 가는가           |
| `tool-failure` | 선택한 실패 지점과 복구/종료      | 정상 / 기간 불일치 / 형식 오류 / 접근 거부 | 실패마다 다음 행동이 다름        |
| `policy`       | 사전 정의한 세 경로의 차이        | 내부만 / 비용 우선 / 품질 우선             | 추가·생략한 작업을 비교          |
| `accounting`   | 도구 호출·모델 호출·재시도 횟수   | 경로에서 자동 계산                         | 횟수가 실제 비용이나 품질은 아님 |
| `final-answer` | 확보한 근거와 확인할 수 없는 부분 | 조작 없음                                  | 도구 성공과 업무 성공을 구분     |

### 경로 데이터의 규칙

첫 구현은 미리 정의한 노드와 연결로 동작한다. 실시간 라우팅 모델은 없다. 입력란에 회사 자료를 업로드하거나 API 키를 넣는 기능도 없다.

- ‘내부만’은 외부 모델 노드를 연결 대상에서 제외한다. 비용·품질 우선 모드에서는 예시상 허용된 외부 모델만 선택한다.
- 기간 불일치는 검색 조건을 바꾸는 경로다. 형식 오류는 입력 정리 후 한 번 재시도한다. 접근 거부는 추가 접근을 시도하지 않고 부족한 자료를 표시한다. 이 재시도 상한은 화면 설명을 위한 예시 정책이다.
- 실패 유형은 다른 모드로 전환해도 유지한다. 경로를 바꿔도 접근 거부가 자동 성공으로 바뀌어서는 안 된다. 초기화는 ‘내부만 + 정상’으로 돌아간다.
- 횟수는 실제 선택된 경로의 노드를 세어 계산한다. 원화·달러·초·정확도는 실측이 없으므로 표시하지 않는다. 경로 수가 늘면 품질이 자동으로 높아지는 게이지를 만들지 않는다.
- 흐르는 강조선은 순서를 설명한다. 선 길이와 이동 속도는 실제 지연 시간이 아니다. 캡션에서 개념도를 명시한다.

| 범위                               | 근거                                                                     | 초안에서의 사용                           |
| ---------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------- |
| 오케스트레이터와 도구 구성         | [ToolOrchestra v1 §3·§4·Appendix D](https://arxiv.org/html/2511.21689v1) | 외부 모델을 포함한 조합이라는 설명        |
| HLE 비교                           | 같은 논문 Table 1                                                        | 텍스트 하위 집합·비교 도구 조건 유지      |

구현 후에는 모든 모드×실패 상태의 조합, 외부 호출 제외, 종료 경로, 카운트 계산, 키보드·모바일·모션 감소 동작을 확인한다. 원고의 정책을 외부 요청이나 실제 모델 호출 없이 설명할 수 있어야 한다.

## AI-03: 같은 표에서 학습할 차이가 생기는 질문

원고: [데이터를 더 넣었는데 왜 좋아지지 않을까?](drafts/ai-03-delta-prompts.md)

| 장면 ID               | 화면과 조작                              | 기본 상태·검증할 내용                                       |
| --------------------- | ---------------------------------------- | ----------------------------------------------------------- |
| `sales-table`         | A=100→120, B=50→70인 가상 표             | 판매량 비교. 2월의 120과 70 강조                            |
| `question-switch`     | 판매량 / 증가율 버튼                     | 증가율 선택 시 20%와 40%를 함께 계산하고 정답 B 표시        |
| `answer-distribution` | 교사·학생의 A/B 확률 막대와 데이터 표    | 판매량은 T=S=[0.9,0.1]. 증가율은 T=[0.1,0.9], S=[0.8,0.2]   |
| `delta-and-quality`   | 두 분포 차이와 정답 근거를 분리          | reverse KL은 0 또는 약 1.363 nat. 성능 예측에 사용하지 않음 |
| `new-problems`        | 실패 스킬 → 문제 후보 → 정답·다양성 확인 | 정적인 작성자 제안. 실제 합성 결과로 표시하지 않음          |

초기화는 판매량 비교로 돌아간다. 모든 확률은 작성자가 고정한 가정이다. 확률의 합=1, 비교 정답, 자연로그 계산, 반올림, 키보드 전환을 검사한다. 질문이 바뀌었는데 정답이나 설명이 이전 상태에 남아서는 안 된다. 막대 아래에 같은 값의 표를 제공한다.

근거는 [DeltaPrompts v3 §2.2·§2.4·§3](https://arxiv.org/html/2605.15532v3)다. 69%는 논문이 조사한 모델·데이터와 추정 절차의 결과로 표시하고, 장면의 가상 두 질문에서 얻은 비율처럼 보여주지 않는다.

## AI-04: 개수와 다양성을 분리해서 보는 행렬

원고: [데이터 10만 개, 얼마나 서로 다른가?](drafts/ai-04-data-diversity.md)

| 장면 ID          | 프리셋·표현                                 | 기대값        |
| ---------------- | ------------------------------------------- | ------------- |
| `all-same`       | A,A,A,A · 전부 같은 유형                    | VS=1          |
| `two-balanced`   | A,A,B,B · 기본 선택                         | VS=2          |
| `two-imbalanced` | A,A,A,B · 같은 두 유형의 비중 변경          | VS≈1.755      |
| `all-distinct`   | A,B,C,D · 서로 다른 유형                    | VS=4          |
| `duplicate-both` | A,A,A,A,B,B,B,B · 균형을 유지하며 수량 증가 | 행 수=8, VS=2 |

같은 유형은 1, 다른 유형은 0인 직교 단위 벡터 내적 커널을 사용한다. 행렬, 유형별 비율, 행 수, 점수는 같은 프리셋에서 계산한다. 초기화는 `two-balanced`다. 셀은 색과 숫자를 함께 표시하고 행·열 머리글을 제공한다. 8×8 행렬은 작은 화면에서 글자와 셀 크기를 확인하며, 설명 표로도 동일한 정보를 읽을 수 있게 한다.

일반 텍스트의 Vendi 계산기는 아니다. 임의 행렬 편집이나 임베딩 업로드 기능은 넣지 않는다. 이 커널에서 비영 고유값은 유형의 비율이므로 `exp(-sum(p*ln(p)))`로 정확히 계산할 수 있다. 유형 수만 세거나 다양성 점수를 정확도 점수로 변환하지 않는다.

근거는 [Vendi Score §3.1·§4.5·Appendix 9.5](https://arxiv.org/html/2210.02410)다. 예제의 행렬과 샘플 이름은 작성자의 설계이며 실제 문장 임베딩으로 표시하지 않는다.

## AI-05: 원문의 근거가 선택형 과제가 되기까지

원고: [문서를 학습 문제로 바꾸는 방법](drafts/ai-05-golden-goose.md)

| 장면 ID          | 화면                                 | 조작·상태                                            |
| ---------------- | ------------------------------------ | ---------------------------------------------------- |
| `source-passage` | 작성자가 만든 릴리스 재현 문단       | 원문과 작성자 예제 표시, 기본 상태                   |
| `mask-reason`    | 두 번째 문장을 감춘 문단             | 가린 근거를 본문으로도 설명                          |
| `pick-option`    | 고정된 A/B/C/D 선택지                | radio group. 초기 선택 없음                          |
| `check-answer`   | 정답 A와 각 오답의 이유              | 선택 후 확인. 다음 선택을 하면 이전 채점 결과를 해제 |
| `quality-review` | 원문 오류·복수 정답·표현 힌트의 검토 | 정적 설명. 통과율이나 학습 효과를 만들지 않음        |

선택지 ID와 표시 순서를 분리한다. 제출 전 정답을 색으로 드러내지 않고, 선택하지 않은 경우의 안내를 제공한다. 초기화하면 선택과 채점 결과를 모두 지운다. 원문 복원 버튼은 학습 실험이 아니라 이해를 돕는 읽기 도구다. 원문과 정답의 연결을 보여주되 ‘진실성 검증 완료’ 같은 상태를 만들지 않는다.

근거는 [Golden Goose v2 §2.1](https://arxiv.org/html/2601.22975v2)다. 화면의 원문·네 선택지·검토 절차는 작성자의 예다. 원 연구의 합성 출력, 선택지 수, 실제 모델 정답률로 오인할 표현을 쓰지 않는다.

## AI-07: 후보·입력·모델 중 무엇이 바뀌는가

원고: [더 오래 생각하기와, 풀면서 배우기의 차이](drafts/ai-07-test-time-learning.md)

| 장면 ID                 | 비교 도식                                | 보존할 구분                                             |
| ----------------------- | ---------------------------------------- | ------------------------------------------------------- |
| `more-candidates`       | 고정 θ₀ → 후보 여러 개 → 평가 → 선택     | 후보 수와 모델 상태를 구분                              |
| `search-feedback`       | 고정 θ₀ → 후보 → 평가 이력 → 새 입력     | 프롬프트·외부 기록 변화, 가중치 고정                    |
| `learn-feedback`        | θ₀ → 후보 → 평가 → 학습 → θ₁             | 모델 갱신이 추가됨. θ₁의 성능 향상은 미리 확정하지 않음 |
| `validity-before-speed` | 정렬 결과 검사 → 유효한 후보의 속도 비교 | 작성자의 실험 설계. 실행하지 않은 수치를 표시하지 않음  |
| `paper-budget`          | 50×512=25,600의 산술과 연구 조건         | 논문 예산·당시 비용 가정·현재 견적을 구분               |

이 글은 정적 비교 도식을 기본으로 한다. 세 방식의 핵심을 전부 본문에 표시하며 숨겨진 탭을 열어야 비교할 수 있게 만들지 않는다. 화면 이동 연출을 추가하더라도 가중치 변화 위치만 강조한다. 모델 파일 다운로드, 코드 실행, 실시간 학습, 성공률 그래프는 현재 설계에 없다.

근거는 [TTT-Discover v2 §2–3·§3.3](https://arxiv.org/html/2601.16175v2)다. 25,600은 생성 후보 예산이다. 다른 비교의 학습 연산량이나 실제 소요 시간까지 같다는 뜻으로 쓰지 않는다.
