# AI 원고 3편: 구현한 읽기 화면

2026-09-10 · 원고와 인터랙션 구현 명세

독자용 본문은 [원고 목록](README.md)의 세 Markdown 파일이다. 긴 글을 기본으로 두고 판단에 필요한 조건이 달라지는 지점에만 조작을 배치했다. 초기 장면 구상을 모두 별도 화면으로 만드는 대신, 계산표와 반례는 본문에서 바로 읽고 필요한 네 예제만 조작한다.

## 공통 읽기 구조

제목 → 논지를 소개하는 문단 → 절별 본문 → 자료 설명 → 세 편의 연결 순서다. 데스크톱에서는 왼쪽 목차가 읽는 위치를 표시한다. 모바일에서는 목차 버튼으로 펼친 뒤 해당 절로 이동한다. 절은 별도 페이지나 Act로 쪼개지 않는다.

본문 폭은 최대 740px이며 작은 화면에서는 여백을 줄인다. 표만 자체 가로 스크롤을 허용하고 긴 코드와 문장은 줄바꿈한다. 본문은 서버에서 정적으로 렌더링된다. 버튼을 누르지 않아도 주장·수치·참고 자료를 읽을 수 있다.

숫자 예제는 설명용 가정이라는 문구를 가까이 둔다. 조작 결과는 문장과 수치로 함께 표시하며 키보드 조작과 초기화를 제공한다. 새 계산 예제에는 자동 애니메이션이 없다. 흐름도는 기존 모션 끄기와 OS의 모션 감소 설정을 따른다.

## 1. 학습과 평가

8개 절: 학습할 문제 진단, 문제별 분포, 생성과 선택, 학습 신호, 논문 결과, 평가기의 오류, 문제별 회귀, 평가 기록.

**생성·선택 계산**은 선택 절 다음에 놓는다. A=[0.9,0.9,0,0], B=[0.25,0.25,0.25,0.25]라는 본문 가정을 사용한다. k=1/2/4/8을 선택하고 B의 정답이 있는 묶음에서 제대로 고르는 비율을 0–100%로 바꾼다. 초기값은 본문 계산과 같은 k=4, 선택 성공 60%다.

`mean(1-(1-p)^k)`로 계산한 B의 정답 포함률과 여기에 선택 성공률을 곱한 최종 성공률을 구분해 표시한다. 기본 결과는 68.36%와 41.02%이며 A의 단일 응답 45%를 비교 기준으로 남긴다. k를 바꿔도 선택 성공률이 유지된다고 가정한 산술이며 모델 성능 예측이 아니다.

SFT·RLVR·OPD, 유한 표본 pass@k, 평균 80→82의 서로 다른 회귀 사례는 정적인 본문과 표로 설명한다. 논문 결과를 가상 확률 곡선 위에 섞지 않는다. 평가기의 순서·장황함 편향과 최종 답만 맞는 모순된 해설을 별도 반례로 다룬다.

## 2. 데이터 설계

7개 절: 판단의 종류, 과제 제작, 독립 검수, 교사·학생 차이, 다양성, 비교 실험, 데이터 버전.

**판매 자료 예제**는 첫 절 다음에 둔다. A=100→120, B=50→70의 동일한 자료에서 판매량 / 증가량 / 증가율 / 기준값 누락을 선택한다. 결과는 각각 A, 동률, B, 비교 불가다. 누락 선택에서는 B의 1월 값만 ‘자료 없음’으로 바뀐다. 초기화하면 원표와 판매량 답으로 복원한다.

합성·검수·선별·학습·평가의 절차는 본문에서 이어 읽는다. 역할마다 별도 애니메이션 화면을 만들지 않는다. 마스킹과 선택지, 교사·학생 분포 차이, Vendi의 유형 커널, 네 비교 실험군은 정적 예제로 보존한다. 같은 생성기와 검사기를 거치며 오류가 반복되는 고리를 끊는 검수와 원문 계보 단위의 분리를 보강했다.

## 3. 추론 시스템

8개 절: 요청 분해, 도구 계약, 조율 모델, 비용, 지연, 탐색과 학습, 구성 복원, 실행 경계.

**요청 도식**은 첫 절 다음에 둔다. Request / Scope / Search / Calculate / Verify / Response의 6개 역할이다. 전체 흐름, 요청과 범위, 검색과 계산, 검증과 응답을 선택하면 관련 연결과 설명이 바뀐다. 계산된 판매 증가와 확인하지 못한 인과관계를 구분한다. 실제 호출이나 처리 시간을 나타내지 않는다.

**라우팅 비용 예제**는 r=20/60/90%에서 `1.5+10r`을 계산한다. 항상 큰 모델을 쓰는 비용 10과 3.5/7.5/10.5를 비교한다. 비용은 가상 단위이고 공통 검색·계산을 양쪽에서 제외했다. 정답률 94.4%와 평균 5초·p95 13초는 본문의 별도 고정 예다. r만 바꾸어 품질·지연을 예측하지 않는다.

**구성 복원 예제**는 공개한 실행 결과 JSON을 표시한다. 기준 / 변경 / 모델 ID만 복원 / 전체 복원의 네 구성을 고른다. 프롬프트와 자료 버전, 관찰 시간, 조립한 입력 문맥을 함께 보여준다. 모델 ID만 복원하면 10분 자료가 남고, 전체 복원하면 기준의 5분 자료가 돌아온다. 합성 자료의 입력 동등성 검증이며 모델을 실제로 호출하거나 응답을 재현한 결과가 아니다. 본문에서 코드와 원본 JSON을 내려받을 수 있다.

TTT의 후보·탐색 이력·모델 상태 차이와 예산은 정적으로 비교한다. 온라인 요청에 학습 버튼을 붙이지 않는다. 마지막에는 모델의 호출 제안과 시스템의 실행 권한을 나눈다.

## 홈과 기존 콘텐츠

OPS / SEC / AI 분류와 검색에서 새 글을 찾는다. AI의 첫 대표 글은 추론 원고이며 기존 MLOps 플랫폼 글도 대표 글 선택지로 남긴다. OPS의 GitLab→응답 확인 8개 요소와 MLOps의 Data→KServe 9개 요소 도식은 유지한다. 원문·실험 기록·파일 저장소·평가·승인·서빙을 구분하며 Knative는 선택 사항이다.

기존 운영 글과 보안 글의 본문·직접 링크는 바꾸지 않는다. 별도 AI 상세 주소만 AI 허브로 연결한다. 소개 문구와 자기소개 수정은 이 구현에 포함하지 않는다.
