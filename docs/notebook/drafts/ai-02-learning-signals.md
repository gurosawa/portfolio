# AI에게 답을 보여줄까, 직접 풀게 할까?

> 이전 분할 초안. 현재 원고는 [학습과 평가 통합 원고](../manuscripts/01-learning-and-evaluation.md)다. 아래 내용은 편집 이력으로 보존하며 별도 발행하지 않는다.

편집 상태: 본문 초안 · 미발행 · AI-02 · 2026-09-10

예정 분류: AI / 개념 설명. 예정 형식: 읽기 중심과 비교 도식. 이 글의 풀이와 피드백 표시는 설명용이며 모델을 학습시킨 결과가 아니다.

## 본문 초안

### 답이 틀렸다는 사실만으로 충분할까

모델에게 `8 + 3 × 4`를 계산하게 했다고 하자. 모델은 8과 3을 먼저 더하고 4를 곱해 44라는 답을 냈다. 정답은 20이다.

이 모델을 개선하려면 무엇을 줘야 할까? 올바른 풀이를 보여줄 수도 있고, 스스로 만든 풀이에 점수를 줄 수도 있다. 더 잘하는 모델이 이 모델의 응답을 보며 학습 신호를 제공하게 할 수도 있다.

여기서 다룰 것은 학습 데이터와 신호를 이용해 모델의 파라미터를 갱신하는 과정이다. 대화창에 설명을 한 번 더 붙이는 것만으로 이 학습이 수행되는 것은 아니다.

같은 산술 문제를 놓고 학습용 응답이 어디에서 오는지 따라가 보자.

### 모범 응답을 따라 학습하기: SFT

먼저 문제와 함께 모범 응답을 준비한다.

> 곱셈부터 계산한다. 3 × 4는 12다. 여기에 8을 더하면 20이다.

SFT에서는 이처럼 준비한 응답을 학습 목표로 사용한다. 모델이 목표 토큰에 부여하는 확률을 높이는 방향으로 학습한다. 이때 데이터의 응답은 사람이 작성할 수도 있고 교사 모델이 생성할 수도 있다. 교사 모델이 만든 응답을 활용하면 증류 방식의 일부가 될 수 있다. [Thinking Machines의 학습 방식 설명](https://thinkingmachines.ai/blog/on-policy-distillation/)

우리 예제에서는 올바른 계산 순서와 답이 이미 데이터에 들어 있다. 준비 과정에서 풀이가 틀리면 모델은 그 풀이를 학습 목표로 받는다. 그래서 모범 응답이 어떤 기준으로 작성·선별되었는지가 중요하다.

SFT를 쓰면 단순 암기만 한다고 단정할 이유는 없다. OpenThoughts3는 수학·코드·과학의 추론 데이터를 체계적으로 구성하고, RL 없이 SFT로 OpenThinker3-7B를 학습했다. 이는 데이터 구성과 학습 조건을 함께 살펴봐야 한다는 사례다. 특정 연구에서의 결과가 모든 업무의 성능을 보장하지는 않는다. [OpenThoughts3 공식 설명](https://www.open-thoughts.ai/blog/ot3)

### 직접 만든 답에 보상 주기: RLVR

이번에는 모델이 먼저 답을 생성한다. 산술 정답을 확인할 수 있는 평가기가 있다고 가정하자. 최종 답이 20이면 보상 1, 그렇지 않으면 보상 0을 준다. 여러 생성 결과와 보상을 이용해 모델을 갱신한다.

검증 가능한 보상을 사용하는 RLVR의 기본적인 형태다. 모델의 행동이 만든 결과를 평가할 수 있다는 조건이 필요하다. 실제 학습법의 손실과 보상 구성에는 여러 변형이 있으므로, 여기서는 최종 정답에만 보상을 주는 예로 한정한다. [RLVR 평가 연구 §2.1](https://arxiv.org/html/2504.13837v5)

44라는 답에 0점을 주면 틀렸다는 신호는 전달된다. 이 신호 자체가 ‘곱셈을 먼저 하라’는 문장을 포함하는 것은 아니다. 학습 알고리즘은 여러 응답과 보상을 통해 갱신 방향을 정해야 한다. 중간 과정을 평가하는 신호를 설계할 수도 있지만, 그것은 지금의 최종 답 채점 예제에 추가되는 조건이다.

보상도 목표를 충분히 반영해야 한다. 산술 문제의 최종 숫자를 확인하는 평가기와, 긴 분석 보고서의 타당성을 확인하는 평가기는 같은 방식으로 만들 수 없다. 우리가 정확히 무엇을 점수로 만들 수 있는지가 학습 설계에 영향을 준다.

### 학생의 응답에서 배우기: On-policy distillation

모범 응답만 따라 배운 학생이 스스로 응답할 때에는 교사가 거의 쓰지 않는 경로로 들어갈 수 있다. 그 경로에서 어떻게 다시 좋은 답으로 이어갈지 배울 기회가 부족할 수 있다.

On-policy distillation은 학생이 생성한 응답을 학습에 사용하면서 교사의 신호를 받는다. GKD 연구는 학생이 만든 시퀀스에서 교사의 피드백을 활용해 학습 시퀀스와 추론 시퀀스의 차이를 다루며, 여러 분포 간 손실을 사용할 수 있도록 구성했다. [GKD 논문 v3](https://arxiv.org/abs/2306.13649v3)

Thinking Machines의 예에서는 학생과 교사가 같은 응답 접두사를 보게 하고 토큰별 분포 차이를 이용한다. 이 구현은 reverse KL을 사용한다. 교사가 자연어로 오답 풀이에 빨간 줄을 그어주는 작업과는 다르다. 토큰별 신호도 모든 토큰의 논리적 옳고 그름을 완벽히 판정한다는 뜻은 아니다. [On-Policy Distillation, Implementation](https://thinkingmachines.ai/blog/on-policy-distillation/)

우리 산술 예제의 비교 도식에는 ‘학생이 생성한 경로’와 ‘그 경로를 조건으로 교사가 제공하는 신호’를 따로 표시한다. 실제 log probability를 측정하지 않았으므로, 진한 색을 정확한 수치처럼 표현하지 않는다.

### 세 이름을 한 줄의 진화 단계로 읽지 않기

아래 표는 이 글에서 설명한 대표 형태를 비교한다. 모든 구현을 포괄하는 분류표는 아니다.

| 비교 항목                  | SFT                              | 최종 답 보상을 쓰는 RLVR | 이 글의 On-policy distillation 예         |
| -------------------------- | -------------------------------- | ------------------------ | ----------------------------------------- |
| 학습 응답을 누가 만드는가  | 준비된 데이터의 작성자 또는 교사 | 현재 학생 모델           | 현재 학생 모델                            |
| 무엇을 기준으로 갱신하는가 | 목표 응답의 토큰                 | 생성 결과에 대한 보상    | 같은 경로에서의 교사·학생 분포 차이       |
| 먼저 준비해야 할 것        | 모범 응답 데이터                 | 문제와 보상·검증 방식    | 교사와 그 신호를 사용할 수 있는 학습 구성 |
| 예제에서 확인할 질문       | 모범 풀이가 올바른가             | 정답 판정이 믿을 만한가  | 교사가 이 문제에서 유용한 신호를 주는가   |

이 셋은 반드시 SFT 다음에 RL, 그다음에 증류로 넘어가는 순서를 뜻하지 않는다. 사용할 데이터와 교사, 검증 방식, 현재 모델의 능력에 따라 선택하거나 조합하는 접근이다. 학습법 이름만으로 필요한 GPU나 전체 비용을 정할 수도 없다. 응답 생성, 교사 평가, 모델 갱신에 드는 작업을 함께 봐야 한다.

### 우리 문제로 돌아오면

산술 모델이 44를 내놓았다는 관찰만으로 학습법 하나가 결정되지는 않는다. 잘못된 사례가 얼마나 자주 나오는지, 이미 가진 데이터가 어떤지, 정답을 어떻게 확인할 수 있는지부터 살펴야 한다.

검토된 문제와 풀이가 충분하다면 그 데이터로 SFT의 기준 결과를 만들 수 있다. 직접 생성한 응답을 신뢰할 만하게 평가할 수 있다면 보상을 사용하는 학습을 검토할 수 있다. 학생의 실패 구간에서 유용한 신호를 주는 교사와 학습 환경이 있다면 on-policy distillation을 검토할 수 있다. 어느 경우든 최종 판단은 학습에 쓰지 않은 별도 평가에서 해야 한다.

모델을 개선하는 일은 ‘정답을 더 많이 보여주자’에서 끝나지 않는다. 어떤 응답을 만들게 하고, 무엇을 근거로 바꾸며, 바뀐 모델이 무엇을 더 잘하게 되었는지까지 이어진다. 다음 글에서는 그 응답을 학습시키는 문제 자체가 충분한 차이를 만드는지 살펴본다.
